# 硬件实机验收入口

## RS485（COM3 ↔ COM6）

`TestStation.PowerSupplyAcceptance` 增加了真实串口入口。它使用软件的
`SerialTransportSession` 打开站端口，另一个端口由同一进程运行 SCPI 模拟电源，
因此命令必须经过两只真实的 RS485 转换器和外部接线才能得到响应：

```powershell
dotnet run --no-build --project tools/TestStation.PowerSupplyAcceptance/TestStation.PowerSupplyAcceptance.csproj -- `
  F:\opencode\TestStation.Replica.Wpf --real-serial --station-port COM3 --emulator-port COM6 --baud 115200
```

该入口会验证连接、`SOUR:VOLT`/`OUTP`/`MEAS:VOLT` 读写、SCPI 错误查询、OpenTAP
自动序列的 `channel_request` 链路以及结束后的串口释放。每次结果写入
`artifacts/real-serial-acceptance/<时间>/`，模拟设备实际收到的命令在 `emulator.log`。

## PCAN

基础传输和通道枚举：

```powershell
dotnet run --project tools/TestStation.PcanProbe/TestStation.PcanProbe.csproj
dotnet run --project tools/TestStation.PcanProbe/TestStation.PcanProbe.csproj -- --loopback
```

应用验收工具还提供 OpenTAP 真实 CAN 通道入口。它发送 `0x5A5 / DE AD BE EF`，
然后由自动序列通过父进程设备服务接收：

```powershell
dotnet run --no-build --project tools/TestStation.PowerSupplyAcceptance/TestStation.PowerSupplyAcceptance.csproj -- `
  F:\opencode\TestStation.Replica.Wpf --real-can --can-tx PCAN_USBBUS1 --can-rx PCAN_USBBUS2
```

`--real-can` 不会退回模拟总线；通道被其他程序占用、驱动缺失或没有总线报文时会明确失败。
使用前关闭 PCAN-View、CanKing 等占用程序，并保证两个通道的波特率和总线终端匹配。

## PCAN 问题修正与实测结果

- PCAN 状态参数为 `0x0D`（十进制 13），硬件名称参数为 `0x0E`。不应将状态参数改为 12。
- 驱动状态 1 表示可用，3 表示 PCAN-View 正在使用但允许连接；两种情况均允许尝试初始化。其他状态保留原始数值，不能据此判断具体占用进程。
- 自动验收原先在发送之后才订阅接收，快速物理帧可能在两个步骤之间丢失。现改为发送前注册订阅，接收设 3 秒超时。
- 自动租约释放与验收退出可能并发，现使用原子转移确保每个会话仅释放一次。
- 真实通道 1→2 的直接收发和 OpenTAP 自动序列均通过；自动序列连续运行两次，进程退出码均为 0，再次探测四个通道均可用。
- 本次为验收专用 CAN 通道后端，证明 OpenTAP 跨进程访问及 PCAN 传输链路可用，不代表已新增正式的通用 CAN 设备家族或协议编辑功能。当前硬件枚举为经典 CAN，不支持据此宣称 CAN FD 已完成实机验证。

此前仅根据 `CanKingService` 正在运行就认定其占用了 PCAN，证据不足，应撤回该结论。
