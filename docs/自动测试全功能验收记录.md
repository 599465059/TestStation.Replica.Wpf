## 发现并修复的问题

首次实际执行暴露 OpenTAP 的步骤嵌套约束：适配序列和复合步骤未声明允许的子步骤，构建计划时提示 `Cannot add test step of type OpenTapBridgeStep to OpenTapSequenceStep`。

已在 `OpenTapSequenceStep` 和 `OpenTapBridgeStep` 上添加明确的 `AllowChildrenOfType` 声明。修复后完整主序列、嵌套调用、循环和异常路径均通过实际运行。初次失败报告保留在 `artifacts/automatic-acceptance/20261025-012511/initial-run`，与最终示例报告分开。

## 重复执行

在源码根目录运行：

```powershell
dotnet run --project tools/TestStation.Acceptance/TestStation.Acceptance.csproj -- F:/opencode/TestStation.Replica.Wpf
```

工具会打开实际 WPF 序列编辑页面、运行 OpenTAP 并生成新的验收证据目录。默认读取现有示例；要恢复生成器默认内容，可加 `--generate`，该选项会覆盖示例序列及模拟数据。`--generate-only` 在生成缺失工程后退出。

单独复核正式EXE启动：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/TestStation.Acceptance/Inspect-Shell.ps1 -RepositoryRoot F:/opencode/TestStation.Replica.Wpf -OutputDirectory artifacts/shell-check
```

## 子序列执行跟随专项验收

新增自动切换到当前执行序列、滚动到高亮步骤的专项验收，使用实际 WPF 页面和 OpenTAP Host，包含两层子序列、重复调用、跨序列相同步骤 ID、暂停/继续及在深层子序列停止。12 项跟随检查全部通过；连同表达式和类型基础检查共37项通过，耗时9.67秒。本次为专项运行，没有重新执行约65秒的全功能主序列。

同时确认页面自动跟随不修改序列、参数或变量定义，主序列正式报告仍以原入口生成，单独调试子序列不生成报告。

证据位于 `artifacts/automatic-acceptance/20261025-214813`：`summary.json` 为检查明细，`execution-follow-transitions.json` 为页面与步骤切换记录，`follow-child-paused.png`、`follow-leaf.png` 为界面截图。
