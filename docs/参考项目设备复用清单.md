## 1. 先看结论

参考工程有 **117 个独立设备模块项目**（排除测试工程、构建临时项目及 IT7900P_Copy 副本）。它们是复用候选清单，**不是 117 个已经验证完成的驱动**。本次按源码逐模块检查目录、设备类、工厂、协议及型号目录，对占位、共享后端及明显不一致单独标注；没有编译、加载插件、运行测试或连接实物。

清单中的“可以用”指有值得提取或适配的源码。任何条目都尚未因此成为本软件已支持设备，也不代表厂商全系列和全部功能均已覆盖。通信栏按能找到的实现路径填写；描述符只声明、未接通的选项会明确标注。

| 分级 | 含义 | 模块数量 |
|---|---|---:|
| A：指令配置优先复用 | 已有 SCPI 型号目录、设备工厂和命令集，适合优先适配；仍需核对命令及规格 | 64 |
| B：专用驱动适配 | 已有协议、设备逻辑或有效工厂路径；需保留专用解析、寄存器或共享核心 | 44 |
| C：配套后端／SDK 适配 | 模块依赖共享运行服务或厂商驱动，不能只复制模块目录 | 5 |
| D：局部参考／暂不可作完整驱动 | 已发现关键通信或操作未接通，仅定义、寄存器或解析等可参考 | 4 |

A/B/C 均是源码复用方式，不是质量认证或实机完成度评分。D 类也列入清单，避免选型时误认为项目中不存在，或误以为已有完整实现。

## 5. 选设备前需要知道的具体差异

1. **USB 声明不等于 USB 通信完成。** 多个 ITECH 描述符列出 USB，但相应工厂实际只在 SerialCommunicationService 与 TcpCommunicationService 中选择。迁移清单因此仅列 TCP／串口；USB-TMC／VISA 需要另查真实实现，不能由下拉选项推定。
2. **IT8211、IT8500 走固定二进制帧。** 它们经 ItechScpiDeviceFactory.CreateFixedFrameDevice 创建 ItechFixedFrameDevice；名字中有 Scpi 不代表实际协议就是 SCPI。
3. **同厂商、同类别也可能不同协议。** PW6001 当前路径为 SCPI，PW8001 当前源码为 Modbus TCP；BP7330 是通过 TCP 传带 CRC 的寄存器帧，不能按普通 Modbus TCP 头直接处理。
4. **UDP 设备需要单独资源支持。** N39240 是 UDP/SCPI，GWS 温箱有 UDP 服务。现有 TCP 虚拟电源不覆盖这些传输语义。
5. **必须排除占位路径。** EA PSB、汉升交流源、ZK-LL1K-150T、Custom-6CH-Insulation 有明确未接通路径。SDC50 同目录既有工厂使用的 Modbus 实现，又有未实现的双向类；ZKAEL0093 则必须走注入实际串口与站号的工厂。
6. **型号数量不能当作硬件完成数量。** AN23600E 的 54 项来自公式生成；IT8200 与 IT8200E 目录重叠；IT-M3200 包含别名、附件／组合标识；IT16000C/D 等只有系列标识。这些都需要在正式接入前去重、核对。
7. **动态插件入口不统一。** LoadedDevicePlugin 反射查找可选 CreateDevice 方法，部分模块只有元数据，实际设备由旧工厂或共享服务创建。因此不能将所有 DLL 复制到我们软件就期望直接运行。
8. **旧设备基类负责采集与重连。** DeviceBase 连接路径会启动采集循环；如果整体照搬，会与我们的手动轮询、自动步骤按需读取、资源独占发生职责重叠。命令和解析值得复用，后台任务必须重新纳入主程序协调。

上述定位依据：[IT6000 工厂](<F:/my-test-system-master/PowerSupply.Modules.ITECH.IT6000/IT6000Factory.cs>)；[固定帧工厂](<F:/my-test-system-master/Load.Modules.ITECH.IT8500/IT8500Factory.cs>)；[动态创建入口](<F:/my-test-system-master/Device.PluginRuntime/LoadedDevicePlugin.cs>)；[设备基类](<F:/my-test-system-master/Device.Core/DeviceBase.cs>)；[EA PSB 工厂](<F:/my-test-system-master/PowerSupply.Modules.EAPSB/EAPSBFactory.cs>)。
