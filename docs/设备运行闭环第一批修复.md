# 设备运行闭环第一批修复

日期：2026-11-02。

## 本批范围

修复参考设备的自动建连、手动访问、轮询、异常回收和二进制响应边界。没有开展第二批整体设备架构迁移，没有迁移全部参考设备，没有操作真实串口/CAN/电源。

## 行为变化

- 连接核心不再执行“仅允许手动”的检查；手动入口仍检查自动占用。自动服务先校验实际通道，再打开需要的实例；失败回滚本次新开的会话，保留原手动连接。
- 连接、完整读写事务及断开共享服务门锁，防止通道选择与查询交错。连接失败、响应错误、超时和取消会清理会话、回写错误并释放租约；清理自身报错时保留原错误和附加诊断。
- 组合后端按相反顺序回滚/结束；一个设备清理失败不会阻止其他设备清理。序列取消不取消资源清理。
- 手动面板包含只写通道、读取、写入及动作按钮。类型、权限和范围在设备服务再次校验，动作使用布尔触发值，查询动作按文本只读通道发布。
- 面板加载/可见状态控制订阅。重建字段不清除可见状态，状态通知不重建读数，错误保留最后有效值；默认仅测量通道 500 ms 轮询。
- 取消订阅不打断已经发出的轮询事务；等单次事务结束后停止后续轮询。自动获取仍等待手动事务结束。隐藏后不会因此意外断开设备。
- WPF 状态和读数通知切回 Dispatcher；宿主释放面板时同时释放 ViewModel 订阅。
- 插件管理使用异步启禁用入口，在统一手动访问门锁内等待家族断开后再更新注册表及通知界面；保存失败尝试恢复家族启用状态。
- 参考 B/C 中尚无真实型号映射的设备移除模板通道并标记不可连接，保留工程配置，避免错误能力被序列调用。

## 传输与协议

IByteTransportSession 增加 ExchangeFramedAsync。协议提供响应头长度和从头部计算总长度的规则，传输层只负责有界的完整帧读取，不引入 SCPI/Modbus 业务判断。

- TCP/串口实现精确收帧、最大长度及超时控制。串口二进制终止符为空时不再向 SerialPort.NewLine 写入非法空字符串；取消/超时通过关闭串口中断 Windows 未完成读取。
- Modbus TCP 按 MBAP 长度收包，校验事务 ID、协议 ID、长度、从站和功能码；RTU 按响应功能码/字节数收包并校验 CRC。
- 写单寄存器/线圈消费并校验响应回显，不留下写确认污染下一次查询；异常帧长度集中校验。
- ITECH 26 字节和 HZP 固定帧使用精确收帧接口。BP7330 保持 RTU-over-TCP，输出使用功能码 05。
- 原通用字节接口保留兼容；未实现精确收帧的后端明确返回不支持，不能静默使用不可靠的空闲间隔替代。
