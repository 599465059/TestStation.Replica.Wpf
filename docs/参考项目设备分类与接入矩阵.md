# 参考项目设备分类与接入矩阵

整理日期：2026-11-01。参考源码：`F:/my-test-system-master`。

这份文档是接入前的源码审计结果。参考项目列出的模块、型号和功能不等于本软件已经支持，也不等于已连接实物验证。接入时必须保留每个设备自己的协议和能力；公共层只提供资源、传输、租约、会话和执行协调。

## 审计结论

- 设备模块清单包含 **117 个**候选模块，按源码目录、工厂、协议或寄存器实现检查。
- A 类主要是 SCPI 型号目录和命令定义，适合先抽取型号能力与命令；B 类需要专用驱动或寄存器/帧解析；C 类依赖厂商 SDK 或共享运行服务；D 类只有局部定义或明确未接通，不能注册为可运行设备。
- 同一设备类别不代表协议相同：PW6001 是 SCPI，PW8001 是 Modbus TCP；IT8500/IT8211 是 ITECH 固定帧，IT8500Plus 是 SCPI；BP7330 是 TCP 上带 CRC 的寄存器帧。
- 参考项目中的 `DeviceBase` 在连接成功后会启动采集定时器，并包含自动重连、操作队列和数据服务发布。迁移时只提取命令、寄存器、帧校验、范围和型号能力；采集、重连和访问优先级由本软件协调器负责。

## 参考项目是怎样使用设备的

典型调用链如下：

```text
工程 deviceInstances.json
  → DevicePluginCatalogService 扫描 device.plugin.json / DLL 或内置插件
  → LoadedDevicePlugin.CreateDevice(configuration, logger, dataService)
  → 设备工厂按 Model + Transport 创建设备对象
  → DeviceBase.ConnectAsync()
  → InternalConnectAsync() 建立串口/TCP/SDK会话
  → 连接成功后 DeviceBase 启动 MeasureAsync 定时采集
  → ReadSignalAsync / WriteSignalAsync / ExecuteActionAsync 访问信号
```

创建配置时，参考项目把 `DeviceInstanceId`、`Model`、`Transport` 和端点参数放进实例配置；型号目录提供能力和范围；设备工厂再决定使用 SCPI、Modbus、固定帧或厂商 SDK。部分模块只实现 `GetSupportedModels`，没有真实 `CreateDevice` 路径，必须视为元数据而非设备驱动。

本软件接入时对应为：

```text
工程设备实例 + TransportResource
  → 具体设备家族模块 / 工厂
  → 具体协议会话（SCPI、Modbus、固定帧、专用协议、SDK）
  → 具体设备驱动（型号能力、通道、命令、解析）
  → IDeviceSession / IChannelRuntimeCoordinator
  → 手动页面和 OpenTAP 通道
```

|---|---|---|---|

| C 类 SDK/共享服务设备 | 保留目录与依赖说明，SDK/任务生命周期及设备映射尚未完成；暂不可连接 |
| D 类 | 参考实现本身未完成，继续不作为可运行设备接入 |

暂不可连接的型号以 RuntimeAvailable=false 明确表达，前台展示原因并禁用连接，设备服务在申请租约之前拒绝连接。工程中的实例、型号 ID 和原序列引用不删除；引用这些未完成通道的序列会明确报错，不回退为内存值。

通用 Modbus 协议已补齐按 MBAP/RTU 帧长接收、事务/功能码/地址/CRC/写确认校验及功能码 05；这仍不代表上述 Modbus 设备的寄存器映射已经完成。BP7330 的 RTU-over-TCP 及写确认接收边界已经整理，设备入口继续待核对后开放。

后续逐个家族补齐通道、范围、指令、解析和模拟验收，再开放 RuntimeAvailable。不可仅修改可用标志或安装 DLL 后宣告设备可用。

## 建议接入批次

1. **协议基线**：完成 TCP、串口 RS232/422/485、UDP、VISA 和 CAN 的通用传输契约；补齐二进制响应的长度/帧读取能力。
2. **SCPI 设备**：ITECH IT6000 家族 → IT8500Plus / IT8800 负载 → PW6001 与 DG1022Z，验证同一协议在不同设备能力上的差异。
3. **Modbus 设备**：C3000 → PW8001 → TOMILO/LG 水冷机 → 温箱；每个设备独立寄存器模型和通道定义。
4. **专用协议**：BP7330、ITECH 固定帧、SARS-F、HZP、同州维普、GWS/N39240。
5. **任务型硬件**：NI DAQ、ART DAQ、NI FPGA、ZLG CAN；单独设计连续采集、共享总线和 SDK 释放。

## 接入台账字段

每个后续设备必须记录：设备家族、型号标识来源、实际协议、传输资源类型、协议会话、通道/动作、范围与单位、连接参数、是否有真实 `CreateDevice` 路径、是否依赖外部 SDK、手动轮询策略、自动步骤映射、模拟器覆盖范围、实机验证状态和已知限制。

这份矩阵完成的是“先理清再接入”。它没有把任何新设备注册到主程序，也没有宣称参考项目的旧页面、采集线程或旧生命周期已经迁移。
