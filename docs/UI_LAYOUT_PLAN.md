# 界面布局优化方案（2026-11-01）

本方案面向“手动控制设备 + 编写自动测试序列 + 设备插件热插拔”的工业测试软件。可交互原型见 `docs/ui-mockup/layout-mockup.html`（浏览器打开，标题栏太阳图标切换深浅主题，左下角按钮收起导航，点输出开关可看全局联动；设置页的外观分类可以切换主题和四种强调色，搜索框可以试“超时”“日志”），各页截图在 `docs/ui-mockup/screens/`。原型使用 `UiTheme.*.xaml` 的现有颜色，新增令牌在第 7 节列出。

## 1. 结论：加“工作台”，“工程预览”放进起始页

两类页面解决的问题不同。工作台回答“这个工位现在能不能开始测试”：设备是否在线、哪台在输出、最近一次运行结果、插件是否齐全，打开工程后每天都要看。工程预览回答“我要打开的是哪个工程”，只在选择工程时有用，单独占一个导航入口不值得。

所以建议：新增“工作台”作为打开工程后的首页，替换现在的 `OverviewView`（它只显示工程名、路径、序列数和模拟通道数，信息不够做首页）；工程预览做成起始页右侧的预览区，选中最近工程时显示序列数、设备数、最近运行结果，以及“需要但未安装的插件”。

## 2. 现状问题（对照 2026-11-01 的 4 张截图）

| 位置 | 现象 | 原因 |
|---|---|---|
| 收起的导航 | “设备测试”和它的子项同时显示为实心蓝块；子项图标在 76px 宽度里挤成一列，看不出层级；点父图标是展开/收起，不是切换页面 | 导航有两级，`NavigationView` 收起模式把子项也画在图标栏里，父子都用 `ActionAppearance.Primary` 高亮 |
| 展开的导航 | “HIOKI PW6001 功率分析仪”被截断；每装一个设备插件导航就多一行 | 设备家族直接作为导航子项 |
| 设备页（电源） | 实例、型号、资源三个下拉框和连接按钮挤在顶部，配置和操作混在一页；“输出设定 / 测量读数”标题居中、像表头；输入框横跨半屏；测量卡片很小；“输出开启”是一个小复选框；下方大片空白 | 页面由插件整页提供，没有统一的设备页骨架 |
| 设备页（负载） | 内容只占左上角 500×160 的区域 | 同上，且每个插件布局各不相同 |
| 通信资源 | “名称”列占 60% 宽度；类型显示小写 `tcp`；诊断区“打开诊断 / 关闭诊断”两个按钮加一段状态文字；发送区和记录区是三块分开的面板 | 表格列宽和诊断区是逐项堆叠的 |
| 全局 | 状态栏只有“已打开：路径”；看不出有几台设备在线、有没有设备正在输出 | 没有全局状态汇总 |

截图右侧悬浮的圆形头像（带红色角标）不属于本软件，是桌面上的其他程序。

## 3. 信息架构

导航改为一级、扁平，每个图标直接对应一个页面。设备家族和设备实例不再进入导航，移到“设备”页内部的列表。这样做有三个好处：收起后点图标就切换页面；插件加载、卸载只影响设备页列表，导航不需要重建；长设备名不会被导航宽度截断。

| 导航项 | 页面内容 | 现有代码 |
|---|---|---|
| 工作台 | 设备状态卡片、最近运行、工程摘要、插件状态 | 替换 `OverviewView` |
| 自动测试 | 现有停靠布局 + 顶部运行条 | `SequenceWorkspace` |
| 手动测试 | 工区标签 + 设备面板平铺 | `ManualTestView` |
| 设备 | 左侧按家族分组的实例列表，右侧设备详情（操作 / 配置 / 通信记录） | 合并 `DeviceTestingView` 与设备实例编辑 |
| 运行记录 | 历史运行列表、报告 | `RunHistoryView`（已存在，未接入导航） |
| 硬件配置 | 通信资源、设备实例两个标签页 | `DeviceManagementView` |
| 插件 | 设备家族插件的加载状态、版本、启用开关、重新扫描 | `PluginManagementView` |
| 设置 | 软件基础设置，页面内有自己的分类导航（见 4.7） | 新增 |

“硬件配置”“插件”“设置”用分隔线放在下方。它们没有放进 `FooterItems`，因为 1.1.0 的页脚是平铺按钮、没有选中态（见 `CONTROL_LIBRARY_GAPS.md` C14）。

导航选中样式统一为“左侧 3px 强调色竖条 + 淡色底”，与表格选中一致。扁平后收起模式每行只有 12px 箭头列 + 40px 图标按钮 + 8px 边距，图标栏可以从 76px 缩到约 64px（宿主需覆盖库构造函数里的 MinWidth 70）。“设备”项右侧显示正在输出的台数，收起后变成一个橙色圆点。

每个页面都用同一个页头：左侧标题和一句说明，右侧最多一个主按钮（强调色）和若干次要按钮。状态栏的“输出中 n 台”只在有设备输出时出现，点击跳到设备页；它是整个界面里唯一常驻的橙色元素，任何页面都能看到。

### 4.2 工作台

```
┌ 设备 ──────────────────────────────────┐ ┌ 最近运行 ─────┐
│ ┌电源01 输出中┐ ┌负载01 已连接┐ ┌万用表…┐ │ │ 01 主序列  通过│

└────────────────────────────────────────┘ ├ 插件 ─────────┤
                                           │ 1 个家族未加载 │
                                           └───────────────┘
```

设备卡片是这页的主体：名称、家族图标、资源、状态标签和两个关键读数（等宽数字）。正在输出的卡片用橙色边框，插件未加载的卡片用虚线框并说明去哪里加载。页头主按钮是“运行主序列”。

### 4.3 设备页

左侧 260px 实例列表，按家族分组，每行一个状态圆点（灰：未连接，绿：已连接，橙：输出中，红：故障）。右侧详情：

```
┌ [图标] 电源 01                               [已连接] [断开] ┐
│ 艾德克斯直流电源，IT6000，虚拟电源 TCP 127.0.0.1:5025          │
├ 操作 | 配置 | 通信记录 ──────────────────────────────────────┤
│ 设定值                     │ 测量值             自动刷新 500ms │
│ 电压   [12.000 ] V         │ ┌电压────┐┌电流────┐┌功率────┐   │
│        0…60 V              │ │11.982 V││0.421 A ││5.04 W  │   │
│ 电流限值[1.500 ] A         │ └0.4秒前─┘└────────┘└计算值──┘   │
│ [应用设定] [读取一次]       │                                  │
├──────────────────────────────────────────────────────────────┤
│ ⚡ 输出中  关闭前不要断开负载接线……                   [ ●━━ ] │
├ ▸ 通信记录（最近 6 条，可展开）───────────────────────────────┤
```

输入框限宽 260–360px；测量值用 30px 等宽数字并显示“多久前读取”；输出改为开关，打开时整条变为橙色底；实例 / 型号 / 资源绑定移到“配置”标签页。手动测试的面板复用同一个“设定值 + 测量值 + 输出开关”组件，只是更紧凑。

### 4.4 硬件配置（通信资源）

左侧表格，右侧 380px 的“参数”表单和“通信诊断”控制台。表格列宽：名称 40%，类型显示 `TCP`、`RS-232` 等大写名，地址用等宽字体，状态用标签。诊断区合并为一个“打开 / 关闭诊断”切换按钮，记录在上、发送框在下，像终端一样阅读。

### 4.5 自动测试

保持现有停靠布局，只在工具栏下面加一条运行条：状态标签、“第 17 / 40 步：步骤名”、进度条、已用时间、通过数、失败数。运行时不需要在表格里找当前步骤。工具栏分成文档组（新建、保存、未保存标记）和运行组（运行为主按钮，预检、暂停、停止，停止用红字）。

### 4.6 起始页（含工程预览）

左侧最近工程列表，右侧预览：序列数、设备实例数、最近运行结果，主序列名，需要的插件，缺少的插件（橙色），路径。打开之前就能知道缺了哪个插件。

### 4.7 设置

设置页左侧 210px 是页面内导航，顶部有搜索框；右侧是一列设置项，最大宽度 780px。每一项一行：左边是名称和一句说明，右边是控件。改动立即保存，右上角短暂显示“已保存”，不需要“应用”按钮。需要重启才生效的项在说明里写明。

页面内导航分三组。分组依据是“设置保存在哪里”，这决定了换一个工程后设置还在不在：

| 分组 | 分类 | 主要内容 | 保存位置 |
|---|---|---|---|
| 本机 | 常规 | 启动时打开上次工程或显示起始页；最近工程数量、清空；自动保存；关闭前确认；界面语言 | `%LOCALAPPDATA%\TestStation\settings.json` |
| | 外观 | 深色 / 浅色（带缩略图的选项卡）、强调色、跟随 Windows、启动时导航展开或收起、测量值字体 | 同上 |
| | 设备与通信 | 新建通信资源的默认超时、手动轮询间隔、CAN 驱动目录、适配器检测 | 同上 |
| | 安全 | 打开输出前确认；停止 / 断开 / 退出时关闭所有输出；紧急关闭快捷键；“运行期间锁定编辑”显示为固定规则 | 同上 |
| | 执行器 | OpenTAP 执行器位置、停止等待时间（现在写死 5 秒） | 同上 |
| | 插件 | 插件目录、监视目录变化、已停用插件数（跳到插件页） | 同上 |
| | 日志与诊断 | 日志目录（打开）、日志级别、导出诊断包 | 同上 |
| 当前工程 | 报告与记录 | 报告目录、格式、运行记录保留期限 | `project.json` |
| | 序列默认值 | 新建步骤的默认超时和失败处理 | `project.json` |
| 其他 | 开发者 | 控件预览（从“视图”菜单和导航移到这里） | — |
| | 关于 | 版本、运行时和界面库版本、第三方声明 | — |

每个分类标题下面用一个标签写明“本机”或“当前工程”，并给出保存的文件。没有打开工程时，“当前工程”组显示为禁用并提示先打开工程。

搜索框按名称和说明过滤所有分类，结果页每一项标出所属分类，可以直接修改。

“安全”分类里“停止、断开或退出时关闭所有输出”在实现之前必须显示“尚未实现”的提示，原因见第 6 节。

**需要随设置页一起整理的现状：**

- 主题和强调色现在不保存，重启后回到深色蓝色。设置页上线时要持久化。
- 本机数据分散在两个目录：`%LOCALAPPDATA%\TestStationReplica\recent-projects.json`，以及 `%LOCALAPPDATA%\TestStation\` 下的 `logs`、`station-variables.json`、`disabled-plugins.json`。建议统一到 `TestStation`，首次启动时迁移旧文件。
- `TESTSTATION_OPENTAP_HOST`、`TESTSTATION_DRIVER_ROOT` 两个环境变量保留，优先级高于设置页。被环境变量覆盖时，设置项显示“由环境变量 … 指定”并禁止编辑。
- 分层：Application 定义 `IStationSettings`（读取、修改、`Changed` 事件），Infrastructure 实现 JSON 读写（临时文件加替换，写入失败不覆盖原文件），App 的设置页和主题服务只依赖接口。工程级设置走现有的 `IAutomaticWorkspaceService`。

## 5. 插件热插拔对界面的要求

| 要求 | 界面做法 |
|---|---|
| 插件可以在运行中加载 / 卸载 | 导航不包含设备家族；设备页列表和工作台卡片订阅 `IManualPluginViewRegistry.Changed` 刷新 |
| 卸载不能丢配置 | 设备实例保留在列表里，显示“插件未加载”，配置标签页仍可查看 |
| 卸载被占用的插件 | 先列出占用的设备、手动面板和序列，确认后再卸载；运行中禁止卸载 |
| 各家插件外观一致 | 插件提供“设定项、测量项、输出开关、专属配置”的描述，宿主统一绘制；保留 `CreateView` 作为专属配置页的扩展口 |
| 插件加载失败 | 插件页显示原因，例如“缺少依赖 HiokiComm.dll”，并提供“打开插件目录”“重新扫描” |

建议在 `IManualPluginViewProvider` 旁新增一个可选的设备面板描述接口（设定项列表、测量项列表、是否有输出开关），由宿主生成 4.3 的操作区。没有实现该接口的旧插件继续用 `CreateView` 整页显示。

## 6. 安全相关的界面行为

输出状态是测试台最需要醒目的信息，所以“输出中”在三处同时出现：设备卡片橙框、导航角标、状态栏标签。原型里设备页的提示文字写了“停止序列、断开连接或关闭软件时会先关闭输出”，这是**目标行为，当前代码还没有实现**（代码审查发现 Stop 时 CLEANUP 不执行、断开时不发 `OUTP 0`）。界面改版前需要先实现这部分，否则提示会误导操作人员。
